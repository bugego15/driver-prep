## 一、90 秒逐字稿（主版本：AI 芯片 / 加速卡驱动岗）

**【0:00–0:10｜定位】**
"面试官好，我叫张文斌，7 年嵌入式系统软件经验，一直在杭州，主要做固件、驱动和 BSP。"

**【0:10–0:35｜核心项目：动态数字信号采集系统】**
"最近一年负责动态数字信号采集系统：3 个背板、24 块 FPGA 采集板，i7 工控机跑 Linux。FPGA 把 AD7768 采到的数据写进 DDR3，再通过 PCIe 2.0 的 XDMA 搬到主机。我负责主机侧环境搭建、XDMA 驱动的编译部署和压测，也做 FPGA 侧 PCIe/DDR3 读写和 bypass 交互——**这套系统的核心就是 DMA 和中断的数据通路**。"

**【0:35–0:55｜横向经验】**
"另外在压力带采集系统里做过 RK3568 的 SDK 裁剪、镜像烧录、USB/FTDI 采集接口和 SD 存储线程；业余自己写了 sixlinux，用 Yocto 打通 TF-A、U-Boot、Linux 启动链，做设备树、MMIO/IRQ 外设和 OTA 升级。"

**【0:55–1:20｜差异化 + 转型动作】**
"我的特点是**设备端和主机端都做过**：既懂硬件和固件怎么想，也能在 Linux 侧定位问题。为了转 host 驱动，我最近自己给 QEMU 的虚拟 PCIe 卡写了一套驱动——BAR/MMIO、MSI-X 中断、一致性 DMA；也在真实工控机上分析过 PCIe 交换芯片拓扑、链路速率和 /proc/iomem 资源分配。"

**【1:20–1:30｜收尾】**
"我希望把系统级调试经验用到原厂 SDK 和加速卡、存储控制器的驱动上，**这也是我投这个岗位的原因**。"

## 五、面试官高频追问 & 回答思路

| 追问 | 回答要点（别踩坑） |
|---|---|
| "XDMA 驱动是你写的吗？" | **诚实**："XDMA 是 Xilinx 的厂商驱动，我负责编译、集成、参数调试和压测排障；为了补上自研驱动经验，我自己写了 QEMU 虚拟卡的 PCI 驱动。"（然后讲自研细节） |
| "24 块卡怎么同步？" | 背板共用 10M 恒温晶振和 start/stop 线，主背板拉 sync 触发同步采集；PCIe 侧只负责搬运，不参与同步。 |
| "DMA 带宽多少？瓶颈在哪？" | 讲方法：压测（fio/自写工具）、perf/中断计数、FPGA 侧计数；如记得数字就说，不记得说"典型值范围 + 测试方法"。 |
| "丢数据/掉卡怎么排查？" | dmesg/AER → DMA 描述符与完成计数 → FPGA 侧状态 → 时钟/同步，分层排查。 |
| "为什么转驱动/为什么离开？" | 方向明确：长期做底层系统软件；现有经验（固件+host 侧）支撑；不说前公司坏话。 |
| "你写的 edu 驱动有什么细节？" | BAR 探测与映射、MSI-X 单向量、DMA mask 32 位、ioctl/mmap、多进程。 |
| "PCIe 2.0 和 5.0 区别？" | 速率/编码/带宽预算，驱动架构不变；链路速率和宽度是协商出来的。 |
| "你对我们要做的产品怎么理解？" | 国产 AI 芯片全栈；驱动 + 运行时 + 工具链是基础软件核心；"内存/调度"是驱动岗核心。 |
